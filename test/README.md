# 测试目录

本目录包含 Aira 工作流系统的测试用例和演示代码，按照测试类型进行了分类组织。

## 📁 目录结构

```
test/
├── unit_tests/              # 🔬 单元测试
│   ├── __init__.py
│   └── test_code_node.py        # CodeNode 功能单元测试
├── integration_tests/       # 🔗 集成测试
│   ├── __init__.py
│   ├── simple_demo.py               # 简单工作流演示 (Start → LLM → Answer)
│   ├── run_demo.py                  # 交互式演示运行器  
│   ├── code_node_integration_test.py # CodeNode 集成测试 (Start → Code → Answer)
│   └── run_code_integration.py      # CodeNode 集成测试运行器
└── README.md               # 本文件
```

## 🎯 测试分类

### 🔬 单元测试 (unit_tests/)
测试单个组件的功能，**不依赖 langgraph**：
- **独立性**: 直接测试节点类的方法和功能
- **快速性**: 无需构建完整工作流，执行速度快
- **覆盖性**: 测试各种边界情况、错误处理和功能点
- **隔离性**: 每个测试用例相互独立，便于调试

### 🔗 集成测试 (integration_tests/)
测试完整的工作流功能，**基于 langgraph**：
- **真实性**: 使用完整的工作流图结构和状态管理
- **交互性**: 支持用户交互、API调用和实际场景
- **演示性**: 展示实际使用场景和最佳实践
- **端到端**: 从输入到输出的完整流程测试

## 🚀 运行方式

### 1. 单元测试

```bash
# 进入单元测试目录
cd test/unit_tests

# 测试 CodeNode 完整功能（包括numpy外部库测试）
python test_code_node.py
```

**单元测试特性**：
- ✅ 数学计算测试
- ✅ 字符串处理测试  
- ✅ 数据分析测试
- ✅ 错误处理测试
- ✅ 外部库引用测试 (numpy)
- ✅ 输出过滤测试

### 2. 集成测试和演示

```bash
# 进入集成测试目录  
cd test/integration_tests

# 运行简单工作流演示（多种模式）
python run_demo.py [模式] [选项]

# 运行代码工作流演示
python code_workflow_demo.py
```

**集成测试模式**：

#### 交互式模式 (默认)
```bash
python run_demo.py interactive
python run_demo.py interactive --mock  # 使用模拟回复
```
- 实时用户输入和对话
- 可以测试各种问题类型
- 输入 'quit' 退出

#### 批量测试模式
```bash
python run_demo.py batch
python run_demo.py batch --mock  # 使用模拟回复  
```
- 运行预设的5个测试用例
- 自动化测试完整流程
- 生成测试报告

#### 快速验证模式
```bash
python run_demo.py quick
python run_demo.py quick --mock  # 使用模拟回复
```
- 单一"你好"测试
- 快速验证系统正常性
- 适合CI/CD流程

## 🧪 测试特性详解

### 🎭 Mock 模式支持
- **无API依赖**: 所有集成测试都支持 `--mock` 参数
- **开发友好**: 无需真实 API 密钥即可测试完整流程  
- **CI/CD适配**: 适合自动化测试环境

### 📊 全面测试覆盖

#### 单元测试覆盖范围：
- **数学计算**: 加减乘除、平均值等基础运算
- **字符串处理**: 文本操作、格式化、分割等
- **数据分析**: 列表处理、统计计算、排序等
- **外部库引用**: numpy数组操作、矩阵运算等
- **错误处理**: 异常捕获、错误信息、边界条件
- **输出过滤**: 结果筛选、安全性控制

#### 集成测试场景：
- **基础问候**: 测试基本对话能力
- **天气查询**: 测试信息查询场景
- **知识问答**: 测试知识型问题处理
- **数学计算**: 测试计算能力
- **创作能力**: 测试生成型任务

### 🏗️ 工作流架构

集成测试中的简单工作流结构：

```
[Start] → [LLM] → [Answer]
```

- **Start 节点**: 接收用户输入，初始化工作流状态
- **LLM 节点**: 处理用户问题（支持真实API或模拟回复）
- **Answer 节点**: 格式化并输出最终答案

## 📈 扩展和定制

### 添加新的单元测试
1. 在 `unit_tests/` 目录创建新的测试文件
2. 直接导入和测试目标组件
3. 不依赖 langgraph，专注功能测试

### 添加新的集成测试
1. 在 `integration_tests/` 目录创建新的演示文件
2. 使用 langgraph 构建完整工作流
3. 集成真实场景和用户交互

### 自定义测试场景
- 修改 `run_demo.py` 中的测试用例
- 添加新的工作流节点类型
- 集成外部API和服务

## ❓ 常见问题

### Q: 单元测试和集成测试有什么区别？
A: 单元测试直接测试组件功能，快速且独立；集成测试使用 langgraph 测试完整工作流，更接近实际使用。


### Q: 如何添加新的外部库测试？
A: 在单元测试中修改 safe_globals，添加 `__import__` 支持，然后在测试代码中正常 import 即可。

### Q: Mock 模式什么时候使用？
A: 开发阶段、CI/CD、无网络环境或不想使用真实API时使用 `--mock` 参数。
